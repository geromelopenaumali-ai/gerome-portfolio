# Automation Animation Initialization Verification

Date: 2026-08-19

## Fix applied

The control-room motion hook now measures geometry synchronously after the component mounts and starts one idempotent `requestAnimationFrame` loop immediately. The previous nested `initialFrame` startup dependency was removed. A `loopRunning` guard prevents duplicate loops, `stopLoop()` centralizes cancellation, and cleanup cancels the active frame and removes every listener.

The loop now uses a stable `animationEpoch`, so motion starts from a predictable initial phase rather than depending on a delayed frame timestamp. Visibility changes stop the loop while the document is hidden and restart it with refreshed geometry when the page becomes visible again. Reduced-motion changes use one feature-detected listener path and stop/reset or restart the loop safely.

## Fresh page load

After loading the homepage without pointer, hover, click, or scroll interaction, the first node was present immediately and its computed transform changed across the first 80 ms and again by approximately 400 ms. The browser reported 13 nodes, visible document state, and reduced motion disabled. Result: automatic startup confirmed.

## Hard refresh

After a hard refresh, the first node was present immediately and its computed transform changed at approximately 100 ms and again by approximately 450 ms, with no interaction. The browser again reported 13 nodes, visible document state, and reduced motion disabled. Result: automatic startup after hard refresh confirmed.
