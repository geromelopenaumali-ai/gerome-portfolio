# Automation Animation and Text Rendering Verification

Date: 2026-08-19

## Root-cause fixes applied

- Replaced the post-paint `useEffect` startup with an SSR-safe `useIsomorphicLayoutEffect` so the client measures the mounted DOM and schedules the first RAF before the first visible paint.
- Removed the node `transform` transition that was competing with continuous inline RAF transforms and causing interpolated, dizzy-looking text during pointer hover.
- Removed the old hover `translateY(-2px)` transform so CSS hover cannot compete with the RAF motion transform.
- Quantized node translations with `Math.round(...)` to avoid unnecessary fractional-pixel card positioning while the nodes float.

## Fresh-load result

The updated homepage loaded with 13 node cards. The first node had a 2D matrix transform immediately. Computed styles confirmed `filter: none` on the node and its strong label, `transform: none` on the text itself, and a transition containing only border-color, background, and box-shadow—not transform. A longer sample confirmed both the node matrix and connected SVG path continued to change over approximately 2.5 seconds.

## Hover result

Pointer movement around the control room preserved the 2D node transform. Computed styles still showed no node filter and no text filter or text transform. The node transition remained limited to border/background/box-shadow properties. The hover coordinate did not land on the first node in the final probe, so tooltip visibility was not used as a pass/fail signal; the rendering constraints were verified directly.

## Build

`pnpm run build` passed successfully after the fixes.

## Interaction and idle result

Pointer movement across the hero did not introduce a transform transition or filter. After three seconds with no interaction, both the first node's transform matrix and its connected SVG path changed, confirming the RAF loop remained active while idle.

## Scroll-return and hard-refresh result

After scrolling away from the hero and returning to the top, the first node transform and connected path both changed over 700 ms while document visibility remained `visible`.

After a hard refresh, the first node transform and connected path changed over 700 ms without interaction. Computed styles confirmed no transform transition and no node filter. The automatic-start check passed.
