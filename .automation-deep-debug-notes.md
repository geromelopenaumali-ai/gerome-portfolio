# Automation Animation Deep Debug Notes

## Root causes identified

1. The motion hook used `useEffect`, so initialization happened after the browser's first paint. The loop was idempotent once mounted, but that post-paint timing could make a fresh hero appear still at entry. The hook now uses an SSR-safe `useIsomorphicLayoutEffect` so geometry and the first RAF request are established before paint on the client.

2. The node CSS had `transition: ... transform .3s ...` while the RAF loop continuously wrote inline transforms. The base hover rule also applied `transform: translateY(-2px)`. This created competing transform interpolation and caused moving node text to look soft or dizzy. The transform transition and hover lift were removed, while border/background/box-shadow transitions remain.

3. The RAF loop now writes whole-pixel 2D translations using `Math.round`, avoiding unnecessary fractional node positioning while preserving the existing floating motion. SVG signal paths continue to update from the live motion offsets.

## Fresh-load verification

After a fresh homepage load, 13 nodes were present immediately, the document was visible, reduced-motion was false, the first node had a 2D transform, and the computed node transition contained no `transform`. The node and text computed filters were `none`.

Whole-pixel transform checks passed on the initial samples. The first node's transform did not change within the first 410 ms because whole-pixel quantization can hold the rendered matrix for several frames, but the longer check confirmed continued movement: the transform changed 3 times over approximately 2.5 seconds and the connected SVG path changed at every sample.

## Build

`pnpm run build` passed successfully after the lifecycle and rendering changes.
